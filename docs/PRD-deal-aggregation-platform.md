## 📝 1.3 細部修改紀錄 (Changelog)
* **v1.22.0 (2026-08-31)**:
  - **🔍 雙核心精準重複情報比對與 1-Char 容錯演算法（Precision Duplicate Deal Detection & 1-Char Fault Tolerance）**：
    - **觸發門檻收斂**：徹底移除過往寬鬆的子字串包含（`includes`）與單純相同來源 URL 判定，僅在「活動名稱」或「活動品項」完全一樣（容錯一個字）時才進行重複比對歸組。
    - **萊文斯坦編輯距離（Levenshtein Distance $\le 1$）**：
      - **活動名稱比對**：標準化字串長度 $\ge 2$ 且編輯距離 $\le 1$（如「那堤」vs「拿堤」、「特大杯美式」vs「中杯美式」差 1 字）。
      - **活動品項比對**：兩卡片商品品項陣列中，存在任一品項標準化後完全一致或編輯距離 $\le 1$（如「布丁冰淇淋」vs「布丁冰淇林」）。
  - **🛡️ 重複情報「全部保留 (不再提示)」與新情報動態比對機制（Keep All & Dynamic Re-triggering）**：
    - **全部保留 (不再提示)**：在 `/admin` 與 `/merchant` 重複提醒橫幅與 `DuplicateDealsModal` 彈窗中，支援「全部保留此組」或「全部保留所有組」。系統將確認配對持久化（`dismissedPairs`），後續不再重複打擾管理者。
    - **新情報到達精準再次比對**：若未來爬蟲或小編發布了**全新的一樣情報**（未在已忽略名單中的新卡片 ID），系統將自動針對該新情報重新發起重複比對提示，完美平衡防打擾與防重複。
* **v1.21.0 (2026-08-31)**:
  - **🐘 遠端資料庫全面持久化（Remote Neon PostgreSQL & Prisma ORM Migration）**：
    - **資料庫實體模型擴充**：於 `prisma/schema.prisma` 新增 `Deal`（特價卡片情報）與 `AdCampaign`（商家廣告投放）資料表，支援完整 7 大要素、品項陣列、支援信用卡、商圈、社群數據與假促銷分析。
    - **全端 DAL 遠端資料庫化**：徹底告別記憶體暫存（`inMemoryDeals`, `inMemoryCampaigns`），所有查詢（`getDeals`）、新增（`createDeal`）、修改（`updateDeal`）、刪除（`deleteDeal`）、批量操作（`batchUpdateDeals`, `batchDeleteDeals`）與狀態切換皆直接寫入遠端 Neon PostgreSQL 資料庫。
    - **資料庫自動種子化（Automatic Remote DB Seeding）**：在遠端資料庫為空或首次啟動時，自動將 87 筆精選特惠情報與廣告活動寫入遠端資料庫，確保服務隨開即用。
    - **過期活動遠端清理（Auto Purge Expired Deals）**：每次查詢時自動在資料庫層清除 `endDate < 今日` 的過期活動，保持資料庫清新高效。

## 🏷️ 三、 標籤系統體系與訂閱機制 (Tag Governance & Subscriptions)

```
┌─────────────────────────────────────────────────────────────┐
│ 頂部副 Header (SubHeaderTagNav):                             │
│ [ All 全部 ]  [ 🌟 我的標籤 ]  [ #咖啡 ]  [ #買一送一 ]  [ 🔥 探索推薦 ] │
└─────────────────────────────────────────────────────────────┘
```

### 3.1 標籤新增 / 訂閱的 2 大標準渠道
1. **渠道一：首頁推薦標籤彈窗（🔥 探索推薦）**：
   - 點擊副 Header 右側「🔥 探索推薦」，開啟官方分類推薦標籤池（促銷、咖啡、超市量販、電商 3C、信用卡）。
   - 點擊「＋ 訂閱」或「✓ 已訂閱」即可即時加入/移除個人上方副 Header 標籤列。
2. **渠道二：搜尋與標籤專屬頁面 (`/tag/[tagName]`)**：
   - 搜尋或瀏覽特定標籤時，頂部專屬 Header 顯示「⭐ 訂閱此標籤」按鈕，一鍵追蹤加入頂部標籤列。

### 3.2 副 Header 標籤列排序與行為規範
* **第 1 項：All 全部**（`selectedTag: null`）➔ 瀏覽全站最新特價。
* **第 2 項：🌟 我的標籤**（`selectedTag: '__MY_TAGS__'`）➔ 聚合呈現使用者已訂閱的所有標籤對應的情報。若未訂閱，引導探索推薦。
* **第 3 項起：已訂閱的個別標籤**（如 `#咖啡`、`#買一送一` 等）➔ 點擊只篩選單一標籤。
* **右側常駐按鈕：🔥 探索推薦** ➔ 彈出官方推薦詞庫庫進行快速訂閱。

### 3.3 會員個人中心頁面 (`/profile`)
* **會員名片**：顯示 VIP 身份、已訂閱標籤數、收藏數、預估省下金額。
* **訂閱標籤集中管理**：查看全部已訂閱標籤、一鍵刪除/取消訂閱、一鍵重置熱門標籤。
* **推薦標籤探索池**：分類瀏覽各維度推薦標籤並支援快速開關訂閱。

## 8. 重複特惠情報比對與 1-Char 容錯演算法規範 (Duplicate Deal Detection & Fault-Tolerant Matching)

### 8.1 核心比對原則與觸發門檻
為避免後台與前台特價情報產生重複、混淆或誤歸組，系統嚴格規範重複情報比對之觸發標準：
**只有在同一通路品牌前提下，當「活動名稱」或「活動品項」完全一樣（容錯一個字）時，才需要且才能進行比對工作與重複歸組。**

```
┌─────────────────────────────────────────────────────────────┐
│ 雙核心比對判定流程 (Two-Core Precision Matching):           │
├─────────────────────────────────────────────────────────────┤
│ 1. 同一通路品牌檢驗 (isSameMerchant) ➔ 通過                 │
│ 2. 核心 1: 活動名稱比對 (Title Match)                       │
│    - 正規化後完全一致 (Exact Match, s1 === s2)              │
│    - 或長度 >= 2 且編輯距離 Levenshtein Distance <= 1       │
│ 3. 核心 2: 活動品項比對 (Target Items Match)                │
│    - 任一品項正規化後完全一致 (Exact Match, s1 === s2)       │
│    - 或長度 >= 2 且編輯距離 Levenshtein Distance <= 1       │
│ 4. 判定準則: isTitleMatched || isItemMatched ➔ 歸入重複候選組 │
│ 5. 若皆不符合 ➔ 嚴格判定為獨立活動，絕不歸組                │
└─────────────────────────────────────────────────────────────┘
```

### 8.2 萊文斯坦編輯距離 (Levenshtein Distance) 與 1-Char 容錯細則
1. **正規化 (Normalization)**：
   - 轉為半形小寫，過濾品牌通用字詞（如「全家」、「7-11」、「星巴克」、「康康5」、「買一送一」等）及所有標點符號與空白。
2. **容錯 1 字門檻 (Fault-Tolerance Gate)**：
   - 兩字串皆須符合 `length >= 2`，避免單一字元（如「茶」與「水」）因編輯距離為 1 而被誤判。
   - 允許 1 次**字元替換**（如「那堤」vs「拿堤」）、**字元插入**（如「美式」vs「冰美式」）或**字元刪除**。
3. **排除過度寬鬆判定**：
   - 徹底廢除任意子字串包含（`includes`）與單純相同來源 URL 即歸組之舊邏輯，杜絕不同品項被混淆串接。

### 8.3 驗收標準 (Acceptance Criteria, AC)
* **AC-1 (活動名稱完全一致)**：同品牌下若兩卡片活動名稱正規化後完全相同，系統應判定為重複，且判定依據標籤高亮 `✓ 活動名稱相符`。
* **AC-2 (活動名稱容錯 1 字)**：同品牌下若活動名稱僅差 1 個字（Levenshtein $\le 1$），系統應精確識別並歸入重複組。
* **AC-3 (活動品項完全一致/容錯 1 字)**：同品牌下活動品項陣列中若有任一品項名稱完全相同或容錯 1 字，系統應識別為重複，並標註相符之商品品項。
* **AC-4 (不同品項/名稱拒絕比對)**：同品牌下若活動名稱與品項差異超過 1 個字（如「拿鐵」vs「美式」），系統絕對不得判定為重複。
* **AC-5 (跨品牌隔離)**：不同通路品牌（如「星巴克」vs「7-11」）即使名稱品項相同，亦不得跨品牌歸組。
* **AC-6 (後台操作反饋)**：在 `/admin` 與 `/merchant` 彈窗中，小編/管理員可預覽重複候選項目、選擇保留特定項目、一鍵合併標籤或批量下架重複項目。
* **AC-7 (全部保留與新情報喚醒)**：
  - 點選「全部保留此組」或「全部保留所有組」後，系統將記錄已確認配對名單（`dismissedPairs`），該組卡片後續將不再提示比對。
  - 當通路有**全新一樣的情報**（未在忽略清單的新卡片 ID）進入系統時，系統將精確重新喚醒該新情報的重複比對工作。

### 8.4 全部保留 (Dismiss/Ignore) 與新情報動態比對架構
```
┌─────────────────────────────────────────────────────────────┐
│ 全部保留持久化與動態喚醒機制 (Keep All & Dynamic Wakeup):   │
├─────────────────────────────────────────────────────────────┤
│ 1. 使用者點擊「全部保留此組 (不再提示)」                    │
│    ➔ 生成配對鍵值 pairKey (如 "dealA_id::dealB_id")          │

│ 3. 爬蟲或小編發布了新情報 dealC (名稱/品項與 dealA 一致):   │
```
